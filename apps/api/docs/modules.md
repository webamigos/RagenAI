# apps/api — Modules

Extracted from `apps/api/AGENTS.md` on 2026-08-31 to keep that file inside the
32 KB agent instruction budget. This is the authoritative module reference for
`apps/api`; AGENTS.md links here instead of inlining it.

- **PrismaModule** (global) — `PrismaService` wrapping `PrismaClient` with `@prisma/adapter-pg`.
- **VaultModule** — `VaultClient` for secure token storage via HMAC-SHA256 signed HTTP requests to an external ragen-token-vault service.
- **CommonModule** (global) — `ApiKeysService`, `ApiKeyGuard`.
- **ChatModule** — Direct implementation (as of the Phase B cutover, not a proxy) — see "Chat" below. **ChatCompletionsModule** — also a direct implementation as of a later Phase B cutover (OpenAI-compatible `/v1/chat/completions`), no longer proxies to ragen-app — see "Chat" below.
- **ThreadsModule** — CRUD for threads + nested messages sub-resource.
- **AssistantsModule** — Assistant CRUD.
- **HealthcheckModule** — Health check endpoint.
- **RagEngineModule** — anchor module for the ported RAG engine — see "Ported RAG-engine libs" below. As of the Phase B cutover, `ChatModule` imports this for real (`/v1/chat`) — it's no longer "not yet wired into any controller."
- **AiUsageModule** (via RagEngineModule) — real, DB-backed (`AiUsageService.track()` writes to the `AiUsage` table). Called from `ChatService` (usage tracking) and threaded into the RAG chain as `trackAiUsage`.
- **OrganizationsModule**, **DocumentsModule**, **TeamsModule**, **ApiLimitsModule**, **ChainsModule** (all via RagEngineModule) — real, DB-backed config/settings-resolution services (org settings, LiteLLM key resolution, API rate limits, the `initializeBasicRag` chain factory). `ChatService` calls `ApiLimitsService`/`OrganizationSettingsService`/`ResolveLiteLLMKeyService`/`InitializeBasicRagService` directly.
- **ConnectorsModule**, **ProjectsModule**, **SecurityModule**, **McpModule** (all via RagEngineModule) — real, DB-backed MCP connector/tool-loading services. `ChatService` calls `LoadMcpToolsService.loadMcpToolsForApiRequest()` directly.
- **ThreadsModule** gained **`PersistApiThreadService`** (`createApiThread`, ported from ragen-app's `persist-api-thread.ts`) — real, DB-backed, uses `src/crypto/thread-encryption.ts` for optional per-thread KMS envelope encryption. Registered as a provider in the *existing* `ThreadsModule` (not `RagEngineModule` — that module already exists with a real, wired `ThreadsController`; this is additive, nothing else in it changed). `ChatService` imports `ThreadsModule` directly (not re-exported via `RagEngineModule`) and calls it when `context.debugMode` is true.

- **NotificationsModule** — Phase C's first slice (see docs/adrs/21-monorepo-and-api-decoupling.md). `NotificationsService` (`create`/`markAllAsRead`/`markAsRead`/`getNotifications`), ported from ragen-app's `src/features/notifications/services/{commands,queries}/*.ts`. Real, DB-backed. No controller yet — same unwired-first pattern as Phase B's slices, `AppModule` imports it directly (not nested under `RagEngineModule`, which is scoped to the RAG/chat engine specifically).
- **MessagesModule** — Phase C's second slice. `MessagesService` (`createMessageInDb`/`createAndStoreMessage`/`deleteMessage`/`rateMessage`/`regenerateAssistantMessage`/`updateMessagePlayed`/`getThreadMessages`/`getNegativeQa`), ported from ragen-app's `src/features/messages/services/{commands,queries}/*.ts`. Real, DB-backed, uses `src/crypto/thread-encryption.ts` (write) and the newly-ported `src/crypto/decrypt-messages.ts` (read) for per-thread KMS envelope encryption. `getOrgIdFromAuthOrThrow()`/`getOrgIdFromAuth()` (ragen-app's session-cookie auth helpers) replaced with an explicit `orgId` parameter on every method that needed them. **Not ported**: `send-message-command.ts` (needs `threads`' `findOrCreateThreadCommand` — deferred to the `threads` slice, last in Phase C's ordering). No controller yet, same unwired pattern, `AppModule` imports it directly.
- **ProjectsModule** — Phase C's third slice. `ProjectsService` consolidates every ragen-app `src/features/projects/services/{commands,queries}/*.ts` (create/archive/delete/rename/star/disablePublicAccess/markIntegrationsPrompted/saveProjectInstruction/saveProjectMcpProviders/revokeProjectShare/shareProject/generateProjectKey/toggleChatbot + queries) plus `services/utils/require-project-access.ts`, now `requireAccess(projectId, level, orgId, userId)` — see "Auth-gate adaptation" in the ADR's Phase C update for the full detail (identity as explicit params, `getActiveMember` replaced with a direct `member.findFirst({organizationId, userId})` lookup using the already-known `userId`, `isOrgAdmin` inlined, `@nestjs/common`'s `UnauthorizedException`/`NotFoundException` used instead of ragen-app's custom `src/libs/utils/errors.ts`). Still shares the `apps/api/src/projects/` directory with the pre-existing `GetProjectMcpProvidersService` (from the MCP slice, needed by `LoadMcpToolsService`) — `ProjectsService.getProjectMcpProviders()` delegates to it rather than duplicating the query. Depends on the two new modules below plus the already-ported `NotificationsService` (for `shareProject`'s notification, DB-write only, no real-time push — same exclusion as the `notifications` slice).
- **AuditLogsModule** (new) — `AuditLogService.track()`, ported from ragen-app's `src/features/audit-logs/services/commands/create-audit-log-command.ts`. Fire-and-forget (never throws), same shape as `AiUsageService.track`/`SecurityEventService.record`. The original derived `orgId`/`userId`/Better-Auth `impersonatedBy` from the session internally (`getSession()`/`getOrgIdFromAuth()`) — now explicit fields on the input, since every caller already has them.
- **SubscriptionsModule** (new, small) — `SubscriptionsService.getEffectiveFeatures()`/`.isFeatureEnabled()`, ported from ragen-app's `src/features/subscriptions/services/queries/{get-effective-features-query,pick-best-subscription}.ts` + `contracts/features.types.ts`. Only this one read path — **not** the full `subscriptions` feature (no billing, no Stripe, no plan CRUD). `ProjectsService.toggleChatbot()` is the only caller so far.
- **ConnectorsModule** — Phase C's fourth slice extended the pre-existing module (from the MCP slice) with `ConnectorsService`: the "core" connector lifecycle — `createConnector`/`disconnectConnector`/`toggleConnector`/`markConnectorConnected`/`registerApiKey`/`registerApiKeyBearer`/`registerApiKeyCustomHeader`/`testCustomHeaderConnection`/`getConnector`/`getUserConnectors`, ported from ragen-app's `src/features/connectors/services/{commands,queries}/*.ts`. Depends on `AuditLogsModule`/`SubscriptionsModule` (same pattern as `ProjectsService`) and the already-ported `ragen-vault` client (`ragenAuthClient`, used directly as a plain import — it's a lazy singleton, not NestJS DI, matching ragen-app's own usage). **Not ported, and not planned**: Google Drive folder import/sync and Fireflies transcript search (~1450 lines) — checked after S3/Temporal landed (see the ADR's 2026-08-30 "S3 + Temporal infra" update) and found to be **ragen-app-UI-only features with no apps/api relevance at all**: every one of `{import,sync}-drive-*-command.ts` is called exclusively from `src/app/actions/google-drive.ts` (a Next.js Server Action backing the project KB import dialog), and `{get,search}-fireflies-*-query.ts` exclusively from `src/app/actions/fireflies.ts` (a Settings > Connectors search panel). Neither is reachable from any `/v1/*` route, planned or otherwise — porting them would serve no purpose. Fireflies MCP *tool* access during chat (a completely different mechanism, already fully ported) is unaffected. `GetEnabledConnectorsService`/`GetAvailableConnectorsService`/the provider registry (all from the MCP slice) are untouched.
- **DocumentsModule** — Phase C's fifth slice extended the pre-existing module (from Phase B's `GetImportedKbFileIdsService`) with six services covering the Knowledge Base UI's metadata/permissions/analytics surface (not upload/storage): `FoldersService` (create/update/move/list/breadcrumbs/PII-policy), `FilesService` (file + markdown-document CRUD, `getUserFiles`'s all/my-files/shared-with-me view modes, project import), `DocumentPermissionsService` (share/revoke/list, notifies via `NotificationsService` on user shares), `VectorPermissionsService` (`computeAccessibleBy`/`syncFolderVectorPermissions` — **security-sensitive**, computes the `accessible_by` Qdrant metadata array that is the actual RAG-retrieval access-control boundary; uses the same `require('@qdrant/js-client-rest')` CJS-interop workaround as `vector-store/qdrant-client.ts`), `DocumentEncryptionService` (batch KMS content-encryption migration), and `KnowledgeAnalyticsService` (the four analytics dashboard reads). Ported from ragen-app's `src/features/documents/services/{commands,queries}/*.ts` (the metadata/permissions/analytics subset). `getOrgIdFromAuthOrThrow()` calls throughout became explicit `orgId` parameters; `getProjectByIdOrThrowQuery` became the already-ported `ProjectsService.getProjectByIdOrThrow()` (new `DocumentsModule` → `ProjectsModule` import, no cycle); `trackAudit`/`sendNotificationToUser` became `AuditLogService.track()`/`NotificationsService.create()`, same pattern as every other Phase C slice.
  - A later slice (the S3/Temporal infra track, see the ADR's 2026-08-30 "S3 + Temporal infra" update) added the upload/delete side: `UploadFileService` (`uploadFile`, ported from `upload-file-command.ts` + the small `create-file-command.ts` it called), `DeleteFileService` (`deleteFile`, ported from `delete-file-command.ts`, reuses `FilesService.deleteFileFromDb`/`deleteDocumentFromDb`), `DeleteFileFromVectorStoreService` (ported from `src/app/api/upload/services/TableService.ts`'s `deleteFileFromVectorStore` — raw vector-store clients, same `require()` interop pattern), and the small pure helpers `parse-file.ts`/`utils/file-type.ts` (ported from `features/documents/utils/file-parser.ts` + `app/lib/utils/{getFileType,getFileExtension}.ts`, adapted for `Express.Multer.File` instead of a web-standard `File`). `DocumentsModule` now also imports `OrganizationsModule`/`StorageModule`/`TemporalModule`. **Still not ported** (needs S3 and/or Temporal beyond the single-file upload/delete path, or isn't reachable from apps/api's endpoints): `delete-folder-command.ts`, `reembed-file-command.ts`, `reembed-folder-with-policy-command.ts`, `score-file-command.ts` + `rag-optimizer/*`.

- **ThreadsModule** gained three more services in Phase C's sixth (and last) slice, added alongside the pre-existing `ThreadsController`/`ThreadsService`/`MessagesService`/`PersistApiThreadService` (all untouched — those back the OpenAI-compatible public API, a completely separate surface): `ThreadsCoreService` (thread CRUD — create/delete/rename/toggle-starred/context add-remove/find-or-create/create-guest — plus the panel-UI listing/search queries — getAllThreads/getSharedThreads/getSidebarThreads/getUserThreads/searchAll/searchThreads/getThreadDetails/getThreadMessagesList — plus `sendMessage`, the `messages` slice's deferred `send-message-command.ts`, finally ported now that `findOrCreateThread` exists), `ThreadSharingService` (share/getThreadShares/createPublicLink/revokePublicLink/getPublicLink/getUserPublicLinks/getPublicThread — public thread links use `bcrypt`, already a root dependency), and `ThreadEncryptionService` (`encryptThreads`/`encryptAllThreads`, the admin-only batch KMS-encryption migration — same shape as `DocumentsModule`'s `DocumentEncryptionService`). Ported from ragen-app's `src/features/threads/services/{commands,queries}/*.ts` + `src/features/threads/utils/export-thread.ts` (landed as `thread-export.ts`, pure functions, no DI). Contracts landed in `thread-core.types.ts` — a new file, deliberately not reusing `dto/*.ts` in this directory (those back the pre-existing OpenAI-compatible surface and share no shape with these). `ThreadsModule` now imports `AuditLogsModule`/`NotificationsModule`/`ProjectsModule`/`MessagesModule` (no cycle — none of those import `ThreadsModule` back). **Not ported**: `track-thread-created-command.ts` (a no-op in ragen-app itself, retained only for backward compatibility with old callers — porting a no-op adds nothing) and `update-thread-model.ts` (a `'use client'` browser `fetch()` wrapper hitting ragen-app's own `/api/threads/:id/model` route — UI glue, not a service). `events.types.ts` (SSE wire-format contracts) was checked and confirmed unneeded — nothing in this slice's in-scope services/utils imports from it.

- **StorageModule** (new) — `S3StorageService` (`upload`/`download`/`delete`), ported from ragen-app's `src/libs/storage/s3-provider.ts`. S3-only — doesn't port the `LocalStorageProvider` dev-fallback ragen-app also has (apps/api's own `.env.example` only documents S3 credentials).
- **TemporalModule** (new) — `TemporalClientService.startWorkflow()`, ported from ragen-app's `src/libs/temporal/client.ts` (`getTemporalClient`). apps/api never runs a workflow itself (that's ragen-worker), only starts one by name — `temporal.consts.ts` duplicates just the `TASK_QUEUE_NAME` + the one `Workflow` enum member (`RUN_FILE_EMBEDDINGS`) apps/api actually starts, same "reference by string name" convention as ragen-app's own AGENTS.md documents.
- **OrganizationsModule** gained `StorageUsageService` (`getStorageUsage`/`getProjectStorageUsage`, ported from `get-storage-usage-query.ts`) and `OrganizationSettingsService.getStorageLimits()` (+ `StorageLimits` type, `defaultStorageLimits` constant) — both added for the upload storage-limit checks.
- **FilesModule** — `FilesController`'s `list()`/`get()` were already direct Prisma (unwired-first from an earlier slice); `upload()`/`remove()` are now also direct (see "Files" below) — imports `DocumentsModule` for `UploadFileService`/`DeleteFileService`.

(`QueryModule` and a worker-facing `AiUsageModule` controller were previously listed here as TODO stubs — neither exists in `app.module.ts`.)
