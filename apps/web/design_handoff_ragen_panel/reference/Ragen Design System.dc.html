Panel design system · v1 proposal

A working tool, not a marketing page

The palette in global.css was already right, so it is kept value-for-value. What this proposal changes is everything around it: one neutral ramp instead of six legacy sets, navy as the action colour in both themes, crimson rationed to two jobs, a 6px radius and a compact control scale, and Barlow Condensed carrying titles so the panel reads as an instrument.

Four control heights, 6px radius, borders instead of shadows.

Toolbars run 28. Forms and tables run 32. Only the primary CTA and the composer send button run 36. shadcn's stock h-9 default is overridden once, centrally.

Radius & elevation
4 sm
6 md
8 lg
pop

Down from 10px. Panels are line drawings — a shadow means the thing floats above the page: popover, dialog, toast, command palette. Nothing else casts one.

Spacing

4 · 8 · 12 · 16 · 24 · 32. Inside a control: 8. Between controls: 8 or 12. Between panels: 16. Between page sections: 24. Everything else is a mistake.

05

Rules that decide arguments

The full list is in ragen-ux-rules.md.
01

Navy acts, crimson marks

One action colour, one marker colour. If crimson also meant "go here", it would stop meaning "this removes something".

02

The composer is the page

Model, attachments and knowledge scope are visible controls inside the composer, never behind a menu.

03

Answers cite or say they can't

Inline markers plus a sources block. An answer with no retrieval says so, in one line, above the text.

04

Nothing centres in an empty pane

Content starts at the top of the safe area. An empty state is a compact block with one action, not a hero.

05

Sidebar: act, then navigate

Actions on top, destinations in the middle, recent threads grouped by day, org and user pinned at the bottom.

06

Sentence case, verbs on objects

"Add document", not "Submit". Empty states are two lines. Errors say what happened, then what to do.
