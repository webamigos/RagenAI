# Lessons

A catalog of non-obvious corrections and gotchas, indexed so an agent (or a human) can check the relevant area before starting nontrivial work in it, instead of re-discovering the same bug. Inspired by `open-mercato`'s `.ai/lessons.md` mechanism.

## How to use this catalog

Before starting a nontrivial task, skim the bullets under the area(s) it touches (not the whole catalog). Each bullet links to a lesson file with four fixed sections: **Context** (what was happening), **Problem** (what went wrong, concretely), **Rule** (the durable takeaway), **Applies to** (scope).

## Adding or updating a lesson

After a nontrivial correction or a non-obvious gotcha (see `AGENTS.md`'s "Post-Task Workflow"):

1. Check whether an existing lesson already covers it — extend that file instead of creating a near-duplicate.
2. Otherwise, add a new file under `docs/lessons/<kebab-case-slug>.md` with the front matter (`title`, `modules`, `areas`, `topics`) and four-section shape shown by any existing lesson.
3. Add one bullet to the relevant `### <area>` section below (create the section if it's a new area).

- [A guardrail evaluated concurrently with the model call it guards loses two races at once](lessons/a-guard-racing-a-model-call-reports-the-wrong-failure.md) — area:testing,architecture; module:web,api; topic:guardrails,promise-all,error-propagation,e2e,route-table,false-red. `Promise.all([evaluateGuardrails(), rephraseAndExpand(...)])` sent a `BLOCK`-refused question to the rephraser anyway, and surfaced whichever promise rejected first. Three causes in sequence, each looking like the answer; the one that kept CI red was a **relative `LLM_ROUTES_PATH`** resolving against a cwd that differs between the two processes in the job, so the table was never read and chain init threw before any rule ran. - [A "test this" box that runs a different path from the real one is worse than no box](lessons/a-test-box-that-runs-a-different-path-is-worse-than-none.md) — area:architecture,ux; module:admin,web,guardrails; topic:guardrails,llm-policy,preview,pii-masking,judge,fidelity. The two obvious ways to build C3's "test this policy" box — a judge in the panel, and judging the pasted text raw — both return a plausible number from a path no turn takes, and the operator sets a threshold from it. A preview has no oracle: a wrong one is attributed to the model being non-deterministic, which is true and not the cause. Run the production path from the process that runs it, reproduce what happens *upstream* of the thing under test (here, Presidio masking — and fail closed rather than judging raw text), show the input the real path saw, and return the number with its boundary rather than a verdict. Phase D's output rules inherit all of it, plus the sliding window. **It then recurred outside guardrails entirely**: the MCP catalogue's *Test connection* passed `allowedProtocols: [parsed.protocol]` and the three runtime call sites passed none, so an `http://` entry was accepted by the form, confirmed working by the button — tool names and all — and refused by every tool load. The divergence was one *option*, not one path: same function, same package, faithful in every respect but the argument that decided the outcome. Diff what a Test box passes against what the real call site passes, not just the function both reach.
