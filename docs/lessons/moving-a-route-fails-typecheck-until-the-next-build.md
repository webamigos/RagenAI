# Moving an App Router page fails typecheck against stale .next/types, and the error blames your code

**Context**: Two pages moved from `app/[locale]/(panel)/settings/` to
`app/[locale]/(panel)/organization/`. Every reference was updated, every test
passed, and `npm run verify` then failed:

```
.next/types/validator.ts(376,52): error TS2344: Type
'"/[locale]/organization/knowledge-analytics"' does not satisfy the
constraint 'AppRoutes'.
```

**Problem**: `.next/types/validator.ts` is generated by `next build` and
enumerates the routes that existed at the time. `turbo` runs `typecheck` and
`build` as separate tasks, and typecheck reads the file the _previous_ build
wrote — the one listing the old paths. So a correct move fails, and the
message points at the new route as though it were the mistake rather than at
the stale file asserting it does not exist. The obvious readings are all
wrong: the route is not misspelled, the `Link` is not mistyped, and
`@/i18n/routing` is not at fault.

Deleting the old page is what makes it visible. Adding a route is fine —
typecheck simply does not know about it yet and nothing references it in a
typed position.

**Rule**: After moving or deleting an App Router page, run the app's build
once before trusting typecheck — `npm run web:build`, then `npm run verify`.
If a `validator.ts` line is the only failure and it names a route you just
created, the file is stale, not the code. CI never sees this, because it
starts from a clean checkout with no `.next/` to be stale.

**Applies to**: `apps/web` and `apps/admin` (both Next.js with typed routes),
any change that renames, moves or deletes a route segment.
