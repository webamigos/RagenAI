# A path-based CI filter fails silently after a directory move — the job just stops existing

**Context**: ADR-29 moved the Next.js app from the repository root into `apps/web/`. The move itself was mechanical and CI stayed green, including on the `dev → main` release PR that carried it.

**Problem**: green was an artifact of the move, not evidence it worked. `evals.yml` triggered on `paths: ["src/libs/chains/**", "evals/**"]`, and GitHub evaluates those against the repo root, where neither directory exists any more. The ADR-29 PR still matched them — its diff contained the *deletions* at the old paths — so the gate ran, passed, and looked fine. Every PR after it matched nothing, and the "Run CI Eval Gate" job silently stopped being created. There is no failure to notice: a workflow that never triggers produces no red X, no skipped job, no annotation. The prompt-eval gate was dead for two days and the only way to see it was to notice an absence. The same file had three further root-relative assumptions behind that dead filter, so fixing only the trigger would have traded a silent skip for a hard failure: `npm run eval:ci` is defined in `apps/web`, not at the root, and the CTRF converter's script and input paths were both root-relative. The identical bug class had also landed in three other places, all green: `e2e.yml` cached `${{ github.workspace }}/.next/cache` (now `apps/web/.next/cache`) with a key built from `hashFiles('src/**/*.ts', …)`, which matches nothing and so returns an empty string — collapsing the cache key to a constant that no longer varies with the source; `stryker.config.mjs` listed `src/libs/db/tenant-scope-guard.ts` in `mutate`, silently dropping this codebase's worst-failure-mode file from the nightly mutation scope while the job kept reporting success; and `.github/CODEOWNERS` pointed six auth, tenant-isolation and crypto rules at paths that no longer match.

**Rule**: path-based CI config **fails open**. A stale glob in `on.pull_request.paths`, `hashFiles()`, a CODEOWNERS rule or a mutation `mutate` list degrades into "never triggers" / "matches nothing" / "empty scope", and every one of those reads as success. So a directory move is not done when the code compiles and the tests pass — grep the whole repo for the old prefix, including files that are not code: `.github/workflows/*`, `CODEOWNERS`, `stryker.config.mjs`, `.gitignore`, `codecov`, `dependabot`. Two specifics worth remembering: `hashFiles()` and `actions/upload-artifact` paths are *always* relative to `GITHUB_WORKSPACE` regardless of a step's `working-directory`, so they need the full `apps/web/...` prefix even when the neighbouring `run:` does not; and when a script lives in a workspace, prefer `npm run <script> --workspace=@webamigos/ragen-web` (npm sets the cwd to that workspace, so the script's own relative `--config`/`--output` paths resolve) over duplicating the script at the root. Finally, add the workflow file itself to its own `paths` list, so a change to the trigger is exercised by the PR that makes it.

**Applies to**: any future move of a directory that CI config names — the remaining absorptions in ADR-32 (`ragen-token-vault`, `ragen-mcp`), and any renaming under `apps/*` or `packages/*`.
