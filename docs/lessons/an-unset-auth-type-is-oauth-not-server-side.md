# An unset `authType` is OAuth, not server-side

**Context**: the MCP catalogue spec moves the list of connectable services out
of code and into `mcp_catalog_entries`. A row needs an `authType`, and
`ProviderDefinition.authType` is optional — five of the eleven manifests (the
Google connectors) leave it unset. The spec picked a value for that case:

> Required here, although `ProviderDefinition.authType` is optional and several
> paths branch on it being undefined. A manifest with no authType seeds to
> `SERVER_SIDE`, which is what those paths already do in effect — stated rather
> than inherited, because "unset" is not an auth shape.

The first half is right and the seed was written that way in A1.

**Problem**: "what those paths already do in effect" is not what they do.
`ConnectorCard` tests four shapes — `api_key`/`api_key_bearer`,
`external_mcp`, `api_key_custom_header`, `server_side` — and a manifest with no
`authType` matches none of them and falls through to the popup at
`authBaseUrl + authPath`. That fall-through *is* the Google flow: it is how
Gmail, Drive, Calendar, Ads and Analytics reach `/auth/google` on the MCP
container.

`server_side` is the opposite branch. It means the MCP service already holds
the upstream credential, so the card skips the popup entirely and flips the
connector straight to `CONNECTED`.

Nothing was reading the rows yet, so nothing broke in A1. The moment the
catalogue became the source of a connector's auth shape, those five connectors
would have reported themselves connected without ever authorizing — and the
symptom is not an error, it is a connector that looks healthy and returns
nothing. The first person to notice would have been a user with an empty inbox.

The value that works is `OAUTH`: **nothing in either app branches on
`'oauth'`**, so every path takes the turn it takes for `undefined` today. That
property — not the name — is what makes it correct.

**Rule**: when moving an optional field into data, do not reason about what its
absence "means". Grep every branch that reads it and find the one the absent
value actually takes, then pick the member that lands on the same branch. A
default chosen from the field's documentation rather than from its call sites
is a behaviour change disguised as a migration — and one that replaces an
authorization step is silent, because the failure looks like the feature
working.

**Applies to**: any enum-ification of an optional field, and specifically to
`McpAuthType` while the catalogue migration is in flight. The seeded values
live in `prisma/catalog/built-in-connectors.json`, generated by
`projectAuthType()` in `apps/web/src/features/connectors/providers/built-in-projection.ts`
and pinned by `built-in-projection.test.ts`.
