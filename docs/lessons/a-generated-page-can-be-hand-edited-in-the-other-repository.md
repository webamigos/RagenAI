# A generated docs page can be hand-edited in the repository it is published from, and the drift test that would catch it only runs where both checkouts exist

**Context**: `configuration/environment-reference.mdx` in the `ragen-docs`
repository is a build artifact. `scripts/docs/generate-config-reference.mjs`
renders it from `PROVIDER_SEAMS` and `FIELD_GROUPS` in `packages/env`, writing
*across* into a sibling checkout, and
`tests/architecture/config-reference-is-generated.test.ts` fails when the
committed file no longer matches what the generator prints. The file carries a
comment saying exactly that, at the top, in the first screenful.

**Problem**: a docs PR edited it by hand anyway — adding a link to a new page
and a paragraph explaining that "optional" here means Ragen *boots* without the
token vault while connectors and API keys fail at the moment you use them. Good
prose, in the wrong repository. Two consequences, neither of them announced:

- The next `npm run docs:config-reference` would have deleted it silently. A
  generator does not merge; it overwrites.
- `npm run verify` in `ragen-app` went red on a commit that touched nothing in
  `ragen-app`, and stayed red on `main`. The drift test degrades honestly when
  the sibling checkout is absent — which is exactly the case in CI — so the
  failure is invisible in the place that reports failures and appears only on a
  developer machine that happens to have both repositories.

**What fixed it**: the prose moved into the `summary` of `TOKEN_VAULT_GROUP` in
`packages/env/src/config-groups.ts`, and the page was regenerated. The
regenerated output is byte-identical to what the hand edit produced, which is
the check worth running: generate to a scratch path with
`CONFIG_REFERENCE_OUT=/tmp/x.mdx npm run docs:config-reference` and diff against
the committed page. `summary` is read by the generator and by nothing else, so
a markdown link in it is safe — and it now carries two paragraphs, which the
renderer handles.

**Rule**: text that belongs to a generated page belongs to the generator's
source, in the repository the generator reads — not to the file it writes.
Before editing anything in `ragen-docs`, check for the "Generated by …" comment;
if it is there, the edit goes into `packages/env` and the page is regenerated.
And a cross-repo drift test that skips when the sibling is missing tells you
nothing on CI: run it locally before merging either side.

**Applies to**: `configuration/environment-reference.mdx` and any future
generated page in `ragen-docs`; `packages/env`'s seam and group tables;
`tests/architecture/config-reference-is-generated.test.ts`.
